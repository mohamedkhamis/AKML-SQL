SQL Prompt-Style Completion Popup

Which approach should we take for the custom autocomplete UI?

A

Custom WPF Adorner Popup (Recommended)

Build a WPF popup as a text view adornment (like StickyScroll/Minimap that already work). The popup renders as a WPF overlay on the editor, positioned at the caret. Uses the same MEF pattern that's proven to work in SSMS 22.

Pros

  • Uses proven MEF adornment pattern (StickyScroll works)
  • Full control over rendering, colors, layout
  • No dependency on VS IntelliSense framework
  • Can exactly replicate SQL Prompt look

Cons

  • More code to write (popup, filtering, keyboard handling)
  • Need to handle z-order and positioning ourselves
B

WPF Window Popup (Separate Window)

Create a borderless WPF Window that appears near the caret. Completely independent of VS editor — just a floating window positioned manually.

Pros

  • Simplest to implement — standard WPF Window
  • Complete independence from VS editor
  • Easy to style exactly like SQL Prompt

Cons

  • Window focus management tricky (stealing focus from editor)
  • May flash/flicker on show/hide
  • Doesn't move with scrolling editor
C

Fix VS ICompletionSource (Current Approach)

Debug why VS's built-in IntelliSense popup doesn't show our completions. Continue using ICompletionSourceProvider + ICompletionBroker.

Pros

  • Least code — VS handles popup, filtering, keyboard
  • Consistent with VS extension conventions

Cons

  • We spent hours and it didn't work in SSMS 22
  • Limited control over appearance (VS default styling)
  • Can't replicate SQL Prompt look exactly
